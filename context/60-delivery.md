# 交付规范

## 一、先判断：这次到底该不该出文件

| 我说的话 | 该做什么 |
| --- | --- |
| 「XXX 是什么」「为什么 XXX」 | **只在对话框里答**，一句话就够。不出文件。 |
| 「帮我生成 / 导出 / 做个 Word / PDF / HTML」 | 出文件。 |
| 「帮我写个报告」但没说格式 | **先问一句**：Word 还是 PDF？ |
| 「怎么实现 XXX」 | 给思路或代码片段，不出文件。 |

**默认不出文件。** 这是硬性偏好，不是风格偏好。多产出一个文件就是多一份要清理的垃圾。

## 二、四类产出的默认标准

### 1. Word / PDF

- 格式见 [`50-doc-format.md`](./50-doc-format.md)，逐条对照。
- 学位论文、开题报告、课程论文：一律按该规范。
- 其他普通文档（笔记、讲义）：至少保证中文字体正确、公式是 OMML、标题层级清晰。
- **PDF 从 Word 导出，不要用 HTML 或 LaTeX 另起一套** —— 除非我明确说要 LaTeX。

### 2. Python 绘图

- 中文必须能显示（SimSun），负号不乱码。
- 论文插图：字号 10.5 磅，`dpi=600`，`bbox_inches='tight'`。
- 坐标轴要有标签和单位；多条曲线要有图例；不要用默认配色糊弄。
- 给出可重跑的脚本，不要只给图片。

### 3. HTML 网页

- 优先**单文件自包含**（HTML + CSS + JS 在一个文件里），除非我要求工程化。
- 响应式：至少手机宽度下不错位。
- 可视化教程 / 攻略类：要有目录和锚点跳转，能一口气看完，也能按需跳。
- 交付时必须附**怎么打开**：`open index.html` 或 `python3 -m http.server 8000`。

### 4. 后端 / 全栈

- 说明三件事：**数据放哪、密钥放哪、怎么启动**。
- 密钥用环境变量，不硬编码，不写进前端。
- 给 `.env.example`，不给真 `.env`。

## 三、部署：不给这一步就是没交付

写完之后必须回答两个问题，缺一不可：

**Q1 本地怎么跑起来？**

```bash
# 纯静态
python3 -m http.server 8000     # 然后开 http://localhost:8000

# Node
npm install && npm run dev

# Python
pip install -r requirements.txt && python app.py
```

**Q2 怎么上线？**

| 类型 | 推荐路径 | 说明 |
| --- | --- | --- |
| 纯静态页面 | GitHub Pages / Vercel / Netlify | 拖进去就有链接，免费 |
| 有后端、要数据库 | WorkBuddy 发布 / Vercel / Railway | 需说明环境变量怎么配 |
| 只在本机看 | `python3 -m http.server` | 明确说「这只在本机能看，别人打不开」 |

**禁止**：只丢一堆 HTML/JS 文件就说「做好了」。
**禁止**：说「你可以部署到服务器上」但不给具体步骤。

## 四、交付时的说明格式

交付完，用三行说清楚：

1. **做了什么** —— 一句话。
2. **怎么用** —— 一条能直接复制的命令或一句操作。
3. **有什么坑** —— 需要我注意的限制（浏览器兼容、依赖、数据来源不可靠等）。

不要写「希望这份文档对您有帮助」。
